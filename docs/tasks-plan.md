### Задача 1. Подключение к защищенной Kafka и конфигурация окружения
* **Статус:** Выполнено (Практика 2)
* **Тип:** Инфраструктура / Конфигурация
* **Связанные требования:** `FR-1`, `FR-7`, `NFR-2`, `NFR-3`, `NFR-4`
* **Описание:** Подключить стартер `spring-kafka` в проект, настроить защищенный протокол `SASL_SSL` с механизмом `SCRAM-SHA-256`. Вынести все параметры подключения (адрес брокера, логин, пароль, уникальный `group.id`, имя топика свечей) в переменные окружения и `application.properties`.
* **Ожидаемый результат:** Сервис успешно инициализирует Kafka-клиент при наличии подключения и не завершает аварийно работу при временной недоступности брокера.
* **Критерии готовности (Definition of Done):**
  - [x] В `pom.xml` добавлена зависимость `spring-kafka`.
  - [x] Переменные `KAFKA_BOOTSTRAP_SERVERS`, `KAFKA_USERNAME`, `KAFKA_PASSWORD`, `KAFKA_GROUP_ID`, `CANDLE_TOPIC` задокументированы в `.env.example`.
  - [x] Секретные данные (логин, пароль, `secretKey`) отсутствуют в открытом виде в исходном коде и Git.
  - [x] Сконфигурирован уникальный `group.id` (`antipin-strategy-group`) для предотвращения конкурентного чтения свечей между студентами.

### Задача 3. Автоматическая регистрация сервиса на платформе
* **Статус:** Выполнено (Практика 2)
* **Тип:** Разработка / Жизненный цикл
* **Связанные требования:** `FR-2`, `NFR-3`
* **Описание:** Реализовать отправку запроса регистрации `account.registration.request` в топик Kafka сразу при старте сервиса, а также обработку входящего ответа `account.registration.result`.
* **Ожидаемый результат:** Сервис регистрируется на платформе, получает подтверждение `status = REGISTERED` и переходит в режим готовности к приему свечей. При получении `REJECTED` сервис логирует причину и блокирует отправку рекомендаций.
* **Критерии готовности (Definition of Done):**
  - [x] Приложение отправляет запрос регистрации при событии готовности контекста (`ApplicationReadyEvent`).
  - [x] Идентификаторы `accountId`, `strategyId`, `serviceName` стабильны между перезапусками.
  - [x] Подписка на топик `account.registration.result` фильтрует сообщения по `accountId`.
  - [x] При статусе `REJECTED` в журнал пишется предупреждение, флаг авторизации сбрасывается в `false`.
  - [x] Подтверждена реальная регистрация на стенде `omsu.7bits.it:9094` (`Account service has been registered.`).

### Задача 6. Реализация торговой стратегии (RSI Reversal)
* **Тип:** Бизнес-логика / Алгоритмы
* **Описание:** Реализовать алгоритм расчета индекса относительной силы (RSI) с периодом 14 свечей. До накопления 14 свечей выдавать `HOLD`, при перепроданности (<30) — `BUY`, при перекупленности (>70) — `SELL`.
* **Ожидаемый результат:** Сервис формирует обоснованные торговые сигналы `BUY`/`SELL`/`HOLD` с динамическим расчетом уверенности (`confidence`) и рекомендуемого объема (`suggestedQuantity`).
* **Критерии готовности (Definition of Done):**
  - [ ] Корректный расчет приростов и убытков за период 14 свечей.
  - [ ] Генерация `BUY` при выходе из зоны перепроданности.
  - [ ] Генерация `SELL` при выходе из зоны перекупленности.
  - [ ] Изоляция состояния индикатора по парам `(runId, instrument)`.
