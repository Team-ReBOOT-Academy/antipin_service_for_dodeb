## 3. Ограничения (Constraints)

1. **Ограничение среды исполнения (`C-1`):** Используется `Java 21 LTS` и `Spring Boot 3.3.4`. Версии Java 24+ (например, Java 27) несовместимы с `kafka-clients:3.7.1` при `SASL_SSL/SCRAM` из-за удаления метода `Subject.getSubject()`.
2. **Ограничение транспорта и авторизации (`C-2`):** Обмен с платформой выполняется только через брокер `omsu.7bits.it:9094` по протоколу `SASL_SSL` (`SCRAM-SHA-256`) с индивидуальным для студента `KAFKA_GROUP_ID = antipin-strategy-group` и `auto.offset.reset = earliest`.
3. **Ограничение торговой логики на этапе Практики 3 (`C-3`):** До реализации индикатора RSI сервис обязан отвечать на каждую валидную свечу строго базовой рекомендацией `HOLD` (`confidence = 0`, `suggestedQuantity = 0`).
4. **Ограничение кодировки конфигурации (`C-4`):** Spring Boot считывает файлы `.properties` в кодировке `ISO-8859-1`, поэтому кириллические значения (ФИО студента `accountName`, учебная группа `groupId`) должны передаваться через UTF-8 переменные окружения или Unicode-последовательности (`\uXXXX`).

## 4. Допущения (Assumptions)

1. **Сетевое время отклика (`A-1`):** Предполагается, что сетевая задержка до брокера `omsu.7bits.it:9094` стабильна (первое TLS/SCRAM рукопожатие укладывается в `max.block.ms = 15000`, а публикация ответа успевает до истечения окна ожидания прогона).
2. **Жизненный цикл регистрации (`A-2`):** Предполагается, что к моменту подачи рыночных свечей платформа уже обработала стартовый запрос регистрации и присвоила сервису статус `REGISTERED`.
3. **Модель хранения на текущем этапе (`A-3`):** На этапе Практики 3 персистентная БД PostgreSQL и периодический `heartbeat` еще не подключены; состояние регистрации хранится в памяти процесса (подключение БД и `heartbeat` запланированы на последующие этапы).

## 5. Риски и меры снижения (Risks)

| ID | Описание риска | Вероятность / Влияние | Мера снижения |
| :--- | :--- | :---: | :--- |
| **R-1** | **Накопленное отставание в общем топике `account.registration.result`.** При большом количестве сообщений в общем топике подтверждение `REGISTERED` появляется в логах с задержкой, пока консьюмер дочитывает очередь до конца. | Средняя / Среднее | Учет лага при тестировании на стенде, фильтрация чужих событий без лишних накладных расходов и фиксация состояния регистрации сразу при получении своего ответа. |
| **R-2** | **Нарушение контракта рекомендации (например, передача объекта `instrument` вместо строки тикера или `groupId="market"` из свечи).** Платформа отклонит все рекомендации сервиса с ошибкой контракта. | Средняя / Высокое | Строгая проверка типов по Главе 8, использование `groupId` студента из конфигурации и покрытие преобразования автоматическими тестами на эталонном сообщении (`FR-5`, `NFR-5`). |
| **R-3** | **Падение слушателя Kafka при поступлении поврежденного или неполного сообщения.** Поток чтения остановится и сервис перестанет отвечать на свечи. | Низкая / Высокое | Перехват ошибок JSON-десериализации и явная предварительная валидация входных полей до обработки без выброса необработанных исключений (`FR-3`, `FR-6`, `NFR-2`). |
| **R-4** | **Случайное логирование `secretKey` при отладке исходящей рекомендации.** Нарушение требований безопасности платформы. | Средняя / Высокое | Запрет вывода полного JSON рекомендации или `secretKey` в лог-сообщения; логирование только безопасных полей (`recommendationId`, `instrument`, `sequenceNumber`, `signal`) (`NFR-3`). |
